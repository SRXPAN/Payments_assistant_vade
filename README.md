# Бот «Оплаты клуба»

Telegram-бот, который хранит список платежей клуба и напоминает в рабочую группу, когда подходит срок. Работает на Cloudflare Workers (бесплатный план), данные лежат в базе Cloudflare D1. Что именно делает бот — в [SPEC.md](SPEC.md).

Все команды ниже выполняются в папке проекта, в терминале VS Code.

## Как обновить бота

1. Измените код.
2. Проверьте, что ничего не сломалось:
   ```
   npm test
   npm run typecheck
   ```
3. Отправьте новую версию на Cloudflare:
   ```
   npm run deploy
   ```
   Бот обновится за несколько секунд, данные в базе не затрагиваются.

Если в папке `migrations/` появился новый файл (менялась структура базы), перед `npm run deploy` выполните:

```
npm run db:migrate
```

Заново регистрировать вебхук нужно только если сменился адрес воркера, токен бота или `WEBHOOK_SECRET`:

```
npm run bot:setup
```

Команды `npm run bot:...` берут адрес воркера (`WORKER_URL`) и секрет (`WEBHOOK_SECRET`) из файла `.dev.vars` и передают секрет в заголовке запроса. В адресной строке браузера служебные страницы не открываются — так секрет не остаётся в истории.

## Где смотреть логи

- **В браузере:** [dash.cloudflare.com](https://dash.cloudflare.com) → Workers & Pages → `club-payments-bot` → вкладка **Logs**. Там видны все обращения Telegram, почасовые запуски проверки и ошибки.
- **В реальном времени в терминале:**
  ```
  npx wrangler tail
  ```
  Оставьте команду работать и нажмите кнопку в боте — строка появится сразу. Остановить: `Ctrl+C`.

Если бот молчит, сначала спросите у Telegram, доходят ли до него обновления:

```
npm run bot:status
```

Нормально: `pending_update_count` равен 0 или быстро падает до 0, поля `last_error_message` нет.

## Как сделать бэкап базы

```
npx wrangler d1 export club-payments --remote --output=backup.sql
```

В папке появится файл `backup.sql` со всеми платежами, журналом и настройками. Сохраните его в надёжное место (в git он не попадает). Делайте бэкап перед каждой миграцией.

Восстановить в пустую базу:

```
npx wrangler d1 execute club-payments --remote --file=backup.sql
```

Платежи и журнал в виде таблиц для Excel владелец может получить прямо в боте: ⚙️ Настройки → 📤 Экспорт CSV. Каждый понедельник бот сам присылает владельцу эти два файла как резервную копию.

Случайно удалённый платёж возвращается без бэкапа: ⚙️ Настройки → 🗑 Корзина.

## Как проверить, что мы в бесплатных лимитах

Лимиты бесплатного плана на момент написания (ноябрь 2026); актуальные цифры — на страницах Cloudflare «Workers → Limits» и «D1 → Pricing».

| Что | Лимит в день | Сколько тратит бот |
|---|---|---|
| Обращения к воркеру | 100 000 | одно на каждое нажатие кнопки или сообщение + 24 почасовых запуска |
| Время процессора на одно обращение | 10 мс | обычно 1–3 мс |
| Чтение строк из D1 | 5 000 000 | десятки на одно нажатие |
| Запись строк в D1 | 100 000 | единицы на одно действие |
| Размер базы | 5 ГБ | килобайты |

Где смотреть:

- **Воркер:** дашборд → Workers & Pages → `club-payments-bot` → **Metrics**. Графики «Requests» и «CPU Time». Если CPU Time стабильно меньше 10 мс и нет ошибок «Exceeded CPU Limit» — всё в порядке.
- **База:** дашборд → Storage & Databases → D1 → `club-payments` → **Metrics**. Графики «Rows read» и «Rows written».
- **Общий расход по аккаунту:** дашборд → Workers & Pages → Overview, блок использования бесплатного плана.

Для клуба с десятками платежей бот использует доли процента от этих лимитов. Если лимит всё же исчерпан, бот перестаёт отвечать до полуночи по UTC, данные не теряются, деньги не списываются.

## Ручной запуск проверки напоминаний

- В боте: ⚙️ Настройки → 🧪 Проверить сейчас — шлёт сегодняшние напоминания заново, даже если они уже уходили.
- Тот же код, что выполняет почасовой Cron (с защитой от дублей и проверкой часа):
  ```
  npm run bot:check
  ```
- Как кнопка «Проверить сейчас», но из терминала:
  ```
  npm run bot:check:force
  ```

## Что бот делает сам

| Когда | Что |
|---|---|
| Каждый день в час платежа (по умолчанию 12:00 по Варшаве) | напоминания: за N дней до срока, в день срока и 4 дня после |
| Каждый понедельник | список давно просроченных платежей в группу и резервная копия (CSV) владельцу |
| При сбое рассылки | сообщение владельцу в личку, не чаще раза в день |

## Важно знать

- **Владелец один** и задан в `wrangler.toml` (`OWNER_ID`). Если владелец потерял доступ к своему Telegram, нового владельца можно назначить только так: вписать его Telegram ID в `OWNER_ID` и выполнить `npm run deploy`. Для этого нужен доступ к этой папке и к аккаунту Cloudflare — держите их у того, кому доверяете.
- **Двухэтапная проверка.** Включите её в Telegram (Настройки → Конфиденциальность → Облачный пароль) и в Cloudflare (My Profile → Authentication). Тот, кто войдёт в любой из этих аккаунтов, получит бота и данные.
- **Смена токена бота.** В @BotFather: `/revoke` → выбрать бота → новый токен. Затем `npx wrangler secret put BOT_TOKEN`, обновить `BOT_TOKEN` в `.dev.vars` и выполнить `npm run bot:setup`.
- **Польские праздники зашиты в код** — список в `src/dates.ts` (`FIXED_HOLIDAYS` и праздники, зависящие от Пасхи). Если в Польше изменят перечень нерабочих дней, поправьте список, запустите `npm test` и `npm run deploy`.
- **Человек, которому отказали или у которого забрали доступ**, не может слать новые запросы. Вернуть его: 👥 Доступ → выбрать человека (🚫) → назначить роль или «Удалить из списка».

## Тестовые платежи

```
npm run seed:remote
```

Добавляет пять платежей с разными сроками (вчера, сегодня, через 3 дня, суббота, через 40 дней), чтобы увидеть все статусы. Потом их можно удалить через ✏️ Изменить.

## Секреты и настройки

| Что | Где лежит | Как поменять |
|---|---|---|
| Токен бота (`BOT_TOKEN`) | секрет Cloudflare | `npx wrangler secret put BOT_TOKEN` |
| Секрет вебхука (`WEBHOOK_SECRET`) | секрет Cloudflare и `.dev.vars` | `npx wrangler secret put WEBHOOK_SECRET`, то же значение в `.dev.vars`, затем `npm run bot:setup` |
| Telegram ID владельца (`OWNER_ID`) | `wrangler.toml` | изменить и `npm run deploy` |
| Часовой пояс (`TZ`) | `wrangler.toml` | изменить и `npm run deploy` |
| Сведения о боте (`BOT_INFO`) | `wrangler.toml` | JSON из ответа `/setup`; менять только при смене бота |

Токен и секрет вебхука нельзя записывать в `wrangler.toml` и другие файлы, которые попадают в git. Для локального запуска (`npm run dev`) они кладутся в файл `.dev.vars` — он в `.gitignore`.

## Первая установка с нуля

1. Установить [Node.js LTS](https://nodejs.org), затем в папке проекта: `npm install`.
2. Создать бота у @BotFather, узнать свой Telegram ID у @userinfobot.
3. `npx wrangler login`
4. `npx wrangler d1 create club-payments` — полученный `database_id` вписать в `wrangler.toml`, туда же `OWNER_ID`.
5. `npm run db:migrate`
6. `npm run deploy`
7. `npx wrangler secret put BOT_TOKEN` и `npx wrangler secret put WEBHOOK_SECRET` (любая длинная строка из латинских букв и цифр).
8. Скопировать `.dev.vars.example` в `.dev.vars`, вписать туда тот же `WEBHOOK_SECRET` и адрес воркера (`WORKER_URL`), выполнить `npm run bot:setup`. Значение `bot_info` из ответа вписать в `BOT_INFO` в `wrangler.toml` (в одинарных кавычках) и ещё раз `npm run deploy`.
9. Написать боту `/start`, добавить его в рабочую группу.
